# AI 议事会（AIDiscussion）

macOS 原生应用：把**多个已登录的 ChatGPT 账号**组成一个可配置的讨论组，各自扮演**立场互斥**的角色，围绕同一议题**独立论述 → 交叉质询 → 收敛出决策**。

全程由应用通过 macOS 辅助功能（AX）API 在你的 Chrome 窗口之间切换完成——不需要人工复制粘贴，也不需要 Selenium / Playwright。

---

## 核心功能

- **多账号讨论组**：每个成员绑定一个已登录的 Chrome Profile，一个讨论组就是一支"团队"。
- **真正的静默后台运行**：不抢占前台输入焦点，也不安装全局键盘 / 鼠标钩子。所有操作都定向发往目标窗口，因此**你可以边跑讨论边正常使用电脑**。
- **窗口可移出屏幕视野**：一键把参与讨论的 Chrome 窗口移出可视区域，讨论 100% 不弹窗打扰；需要看实时页面时再一键移回。
- **自动切到高推理强度**：自动检测网页端的思考强度控件并切到「高」，让每个成员都按深度思考模式作答。
- **联网搜索过渡态识别**：会识别「正在搜索 N 个网站 / Searching the web / 已搜索」等中间状态，不会把搜索占位符当成最终回答读回来。
- **「继续讨论」断点续跑**：中断、报错或手动停止后保留已有发言，点一下从**下一个成员**接着推进，不重复已说过的内容。
- **身份校验 fail closed**：每次发言前核对目标窗口的登录账号，不匹配就立即停止整场讨论——发错人等于整场讨论作废。
- **发言收到即落盘**：每条发言在收到回复的瞬间原子写入数据库，崩溃或强杀后可恢复。
- **零外部依赖**：纯 SwiftPM 工程，Xcode 直接打开即可构建，无需 resolve 任何 package。

## 为什么强调"角色互斥"

所有账号背后都是**同一个** ChatGPT。如果角色设定不互斥，讨论必然退化成互相附和——这是这类应用最大的隐性风险（回声室）。

因此内置的角色模板**刻意只给一个维度，并明确禁止越界**，用"强制片面"换取观点差异：

| 角色 | 只负责 | 明确禁止 |
|---|---|---|
| 批判者 | 找逻辑漏洞、未经验证的假设、失败场景 | 不许提建设性意见，不许肯定任何人 |
| 成本专家 | 估算时间 / 金钱 / 人力开销 | 不许谈体验与技术优雅性 |
| 乐观派 | 找机会与上行空间 | 不许讨论风险 |
| 用户代言人 | 使用体验、学习成本、真实需求 | 不许谈技术实现难度与内部成本 |
| 风险官 | 最坏情况、不可逆后果 | — |
| 执行者 | 可执行性、前置依赖、第一个动作 | 不许评价方案好坏 |

自定义角色时请沿用这个原则：**写清楚"这个角色专门负责挑什么毛病"，并明确它不许越界谈什么。**

## 配置模型

```
DiscussionGroup                 一次讨论的配置（可复用、可持久化）
├─ name / topic                 组名 + 议题（要决策的问题）
├─ participants: [Participant]
│   ├─ displayName              显示名，如「批判者」
│   ├─ rolePrompt               角色设定（制造认知差异的唯一手段）
│   ├─ avatarSymbol / accentHex 头像符号与配色（多成员一眼可分）
│   ├─ profileDirectory         绑定的 Chrome Profile，如 "Profile 3"
│   ├─ emailHint                账号校验标识，用于确认"这个窗口确实是这个账号"
│   └─ enabled
├─ rounds: [RoundConfig]        议程（轮次顺序可配）
├─ consensus: ConsensusRule     收敛规则
└─ moderatorParticipantID       主席成员（留空则取第一个启用成员）
```

### 议程：轮次与可见性

每一轮有三个可配维度：**性质**、**本轮指令**、**可见性**。

| 轮次性质 | 语义 | 默认可见性 |
|---|---|---|
| 独立论述 | 各成员看不到任何人的发言，避免被带节奏 | 不看他人 |
| 交叉质询 | 能看到他人发言并反驳 | 看他人 |
| 收敛决策 | 汇总所有发言，产出最终结果 | 看他人 / 看全部 |

可见性三档：**不看他人** / **看他人**（不含自己上一轮）/ **看全部**。发言人顺序可显式指定；留空则按配置顺序使用全部启用成员。默认议程即「独立论述 → 交叉质询 → 主席收敛」三步。

### 收敛规则

| 规则 | 行为 |
|---|---|
| 主席汇总 | 主席读完所有发言后给出最终决策与理由 |
| 多数投票 | 各成员独立投票取多数；平票时由主席裁决 |
| 一致同意 | 必须全部赞成，否则判定不通过 |
| 主席独裁 | 主席直接拍板，不要求汇总理由 |

投票规则下会要求成员在**最后一行**输出 `VOTE: YES` 或 `VOTE: NO`（全角冒号也接受）。任一成员格式不合规会明确报错指出是谁，而不是静默算错票。同一收敛轮里，**后投票的成员看不到前人的票**——只把本轮之前的发言喂给它，避免从众。

## 快速开始

```bash
swift build
swift test

# 组装可双击的 .app（含 ad-hoc 签名）并安装到 /Applications
bash Scripts/make_discussion_app.sh release
open /Applications/AIDiscussion.app
```

也可以直接双击仓库根目录的 `启动 AI议事会.command`：已安装则直接打开，未安装则自动编译打包后再打开。

用 Xcode 打开：`open Package.swift`，选 `AIDiscussion` scheme 运行。

### 首次使用

1. 在 Chrome 中建立至少两个 Profile，并在每个 Profile 分别登录一个 ChatGPT 账号。
2. 打开应用 → 新建讨论组。
3. 点**配置**：填写议题；检查 / 编辑每个成员的**角色设定**；点**一键分配**从本地检测到的 Chrome Profile 中自动分配不同账号（**随机换一批**可打乱 Profile 池重新分配）。
4. 回主界面授予应用**辅助功能**权限（系统设置 → 隐私与安全性 → 辅助功能），然后点**开始讨论**。

运行中界面按轮次实时显示发言气泡与正在思考的成员，结束后给出决策卡片。中断后底部按钮会变成**继续讨论**，从下一个成员续跑。

## 数据位置

| 内容 | 位置 |
|---|---|
| 讨论组 / 运行状态 / 发言 | `~/Library/Application Support/AIDiscussion/aidiscussion.sqlite` |
| Profile 别名（账号标识） | 同一数据库 |

数据库包含三张表：`discussion_groups`（配置）、`discussion_runs`（运行时状态与最终决策）、`discussion_utterances`（每条发言的 prompt 原文、回复原文、**实际使用的账号**）。每条发言都标注实际账号，因此任何一场讨论都可事后审计。

## 架构概览

```
AIDiscussionApp (SwiftUI)
  └─ DiscussionHubView                 讨论组列表 + 运行界面
       ├─ DiscussionConfigView          成员 / 议程 / 收敛规则配置
       └─ DiscussionOrchestrator        按议程串行推进，逐成员发言
            ├─ DiscussionSessionProviding  会话提供方抽象
            │    └─ ChromeDiscussionSession 锁窗 · 身份校验 · 写入 · 提交 · 读回
            │         └─ ChromeProfileScanner  读取 Chrome profile / 按 profile 开窗
            └─ DiscussionRepository     → SQLite（发言收到即原子落盘）

AIDiscussionCore    零 UI 依赖（可单独作为 library 使用）
```

### 为什么是串行

讨论组**一次只驱动一个会话**：把目标成员对应的 Chrome 窗口置前（或移出屏幕视野）→ 写入 prompt → 提交 → 读回结果 → 切下一位。

并行需要依赖"对后台窗口写入 AX 值"，而部分应用会丢弃失焦窗口的写入或重置焦点，稳定性代价远高于收益。串行路径与"账号切换"复用同一条已验证的代码路径，可靠得多——而且切换窗口只需不到一秒，并没有因此变慢。

## 隐私与安全

- **不读取、不导出、不注入浏览器 Cookie / session token**；账号切换复用 Profile 中已有的网页登录。
- **不安装全局键盘 / 鼠标钩子**（无 `cghidEventTap` 一类的全局事件监听），所有输入都定向发往目标窗口。
- 只读 Chrome `Local State` 中**用户自己给 profile 起的名字**，不读 `gaia_name` 一类的账号字段。
- 遇到验证码 / 人机验证 / 2FA 会停止并提示你处理，不尝试绕过。
- 数据库只保存讨论内容与实际使用的账号标识，用于事后审计。

## 环境要求

- macOS 14+
- Xcode 15+ / Swift 5.9+ 工具链
- Chrome（也支持 Chrome Canary / Chromium / Edge / Brave）
- **辅助功能**权限（驱动网页 UI 所必需）

## 边界

- 所有成员背后都是同一个 ChatGPT，讨论质量完全取决于角色 prompt 的差异化程度。
- 成员数受可用 Chrome Profile 数限制，一个 Profile 只能绑定一个成员。
- 不使用 API 通道做多模型讨论，也不绕过任何验证码 / 人机验证。
